Version de corrections, issue d'une relecture du code de la 0.3.0. Mise à jour recommandée, en particulier si vous utilisez l'accès d'urgence KeePass.

### Sécurité

- **Bouton « Se connecter »** : il vise toujours la dernière sélection. Une entrée KeePass sélectionnée plus tôt pouvait être connectée (connexion d'urgence hors PSM) à la place du compte CyberArk qu'on venait de choisir.
- **Droits d'un lien symbolique** : la fenêtre Droits partait de 777, les droits du lien lui-même, alors que chmod modifie sa cible. Valider sans rien changer rendait la cible accessible à tous. Elle part maintenant des droits réels de la cible.
- **Bureau à distance par mstsc** : une entrée KeePass dont l'hôte ou l'utilisateur contient un retour à la ligne est refusée. Elle aurait pu ajouter des réglages au fichier .rdp (partage des disques…).

### Données

- **Enregistrement d'un coffre sur un partage réseau** : si le remplacement du fichier échouait à mi-chemin, le coffre pouvait ne plus exister que sous `.bak` et la modification être perdue. Le nouveau fichier est maintenant mis en place, ou l'original remis.
- **Fichier modifié dans l'éditeur** : la taille reçue par le serveur est vérifiée. Si l'envoi est coupé, un message indique que le fichier sur le serveur est peut-être incomplet. Vos modifications restent dans l'éditeur, et un nouvel enregistrement renvoie le fichier entier.

### Coffres KeePass

- Verrouiller Windows pendant un enregistrement le laisse se terminer, puis efface les secrets.
- Le journal `urgence.log` accepte deux instances de l'application qui écrivent en même temps. Le verrouillage des coffres ne dépend plus du journal. Une erreur du journal après un enregistrement réussi n'est plus présentée comme un échec, qui faisait ajouter l'entrée deux fois.
- Fermer la fenêtre de déverrouillage pendant le calcul de la clé annule le déverrouillage.
- Les dossiers KeePass dont le nom contient « / » s'affichent, et l'on peut y ajouter des entrées.
- Un champ en double ou sans nom, ou un en-tête incohérent, ne rend plus tout le coffre illisible.

### Sessions

- **SSH** : après une reconnexion, le suivi du dossier du terminal est réinstallé, une seule fois.
- **Bureau à distance en onglet** : « Déconnecter » abandonne une connexion qui ne répond pas. Fermer l'onglet pendant la préparation de la connexion n'affiche plus d'erreur.

### Installation

Téléchargez `CyberArkTerm-0.3.1-win-x64.zip`, décompressez-le et lancez `CyberArkTerm.exe` (Windows 10 ou 11 x64, aucun runtime ni droit administrateur requis). L'empreinte SHA256 est dans `SHA256SUMS.txt`. L'exécutable n'est pas signé : SmartScreen peut demander « Informations complémentaires » → « Exécuter quand même ». Depuis la 0.3.0 ou la 0.2.0, remplacez simplement l'exécutable : vos paramètres sont conservés.

Bug-fix release from a code review of 0.3.0. Updating is recommended, especially if you use KeePass emergency access.

**Security:** the **Connect** button always targets the latest selection: a KeePass entry selected earlier could be connected (emergency connection outside the PSM) instead of the CyberArk account just chosen. The **Permissions** window for a symbolic link started from 777, the link's own permissions, while chmod changes its target: confirming without changes made the target accessible to everyone. It now starts from the target's real permissions. For remote desktop through mstsc, a KeePass entry whose host or user contains a line break is refused: it could have added settings to the .rdp file (drive sharing…).

**Data:** when saving a vault on a network share, if replacing the file failed halfway, the vault could be left only as `.bak` and the change lost; the new file is now put in place, or the original restored. When sending a file edited in your editor, the size received by the server is checked. If the upload is cut off, a message says the file on the server may be incomplete; your changes stay in the editor, and saving again resends the whole file.

**KeePass vaults:** locking Windows during a save lets it finish, then erases the secrets. `urgence.log` accepts two instances writing at the same time, locking vaults no longer depends on the log, and a log error after a successful save is no longer shown as a failure (which led to the entry being added twice). Closing the unlock window while the key is computed cancels the unlock. KeePass groups with "/" in their name are shown and accept new entries. A duplicate or unnamed field, or an inconsistent header, no longer makes the whole vault unreadable.

**Sessions:** after an SSH reconnect, following the terminal folder is set up again, once. In a remote desktop tab, **Disconnect** abandons a connection that does not answer, and closing the tab while the connection is being prepared no longer shows an error.

Download `CyberArkTerm-0.3.1-win-x64.zip`, unzip it and run `CyberArkTerm.exe` (Windows 10 or 11 x64, no runtime or administrator rights needed). SHA256 hash in `SHA256SUMS.txt`. The executable is not signed: SmartScreen may ask "More info" → "Run anyway". Coming from 0.3.0 or 0.2.0, just replace the executable: your settings are kept.
