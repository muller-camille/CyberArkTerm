Un journal de débogage, et un nouvel essai pour afficher les applications distantes PSM dans l'onglet.

### Nouveautés

**Journal de débogage**
- Le bouton **Paramètres** ouvre maintenant un menu : « Paramètres… », **Journal de débogage** (désactivé par défaut, choix mémorisé) et « Afficher le fichier du journal », qui ouvre l'Explorateur sur le fichier.
- Fichier `%LOCALAPPDATA%\CyberArkTerm\debug.log` (5 Mo au plus, plus une génération `.1`). La barre d'état indique « Journal de débogage actif » tant qu'il l'est.
- Il note le déroulement des connexions :
  - requêtes au PVWA (adresse, statut, durée) ;
  - fichier .rdp reçu ;
  - choix entre bureau et fenêtres séparées ;
  - réglages et événements du contrôle Bureau à distance (codes de déconnexion, erreurs d'ouverture de session, messages du serveur) ;
  - connexions SSH (méthodes d'authentification, questions du serveur, clé d'hôte) ;
  - erreurs.
- Il ne contient jamais de mot de passe, de jeton de session, de demande de session PSM (`PSM@***`), de signature, d'en-tête ou de corps de requête, ni le contenu des sessions. Il contient en revanche des noms de serveurs et de comptes : relisez-le avant de le transmettre.

**Applications distantes PSM dans l'onglet (suite de la 0.4.1)**
- En 0.4.1, un PSM a fermé aussitôt la session ouverte comme un bureau, avec « An internal error has occurred ». Cette session démarrait directement la demande de session (`PSM@…`). Or, en mode RemoteApp, un serveur n'accepte en général au démarrage d'une session que ses programmes publiés.
- La session en bureau démarre maintenant le programme publié par le PSM (`||PSMInitSession`), avec le même utilisateur `PSM@…`, qui porte la demande de session. C'est à confirmer avec votre PSM.
- Si la session se termine dans sa première minute, l'onglet propose **Ouvrir en fenêtres séparées**. Ce bouton fait une nouvelle demande au PVWA, et l'application s'ouvre en fenêtres séparées, comme en 0.4.0. Les reconnexions de cet onglet restent en fenêtres séparées.
- Les messages de fin de session donnent les codes de Windows (code, code étendu).

### À essayer avec votre PSM

1. Remplacez l'exécutable.
2. Activez Paramètres → Journal de débogage.
3. Ouvrez un composant PSM en application distante (PSM-RDP…). S'il s'affiche dans l'onglet, c'est réglé. S'il se termine aussitôt, utilisez « Ouvrir en fenêtres séparées ». Le journal (Paramètres → Afficher le fichier du journal) indique ce que le serveur a répondu.
4. Désactivez le journal une fois le problème compris, puis supprimez le fichier.

### Vérifications

- **Tests** :
  - les jetons PSM, mots de passe, signatures et cookies sont masqués ;
  - les requêtes au PVWA sont journalisées sans identifiants ni jeton ;
  - le fichier .rdp du PVWA est décrit sans secret ;
  - le journal passe à la génération suivante au-delà de 5 Mo.
- **Sur un vrai Windows de CI** : un fichier d'application distante s'ouvre comme un bureau qui démarre le programme publié, puis en fenêtres séparées (le Bloc-notes est lancé dans la session ouverte) ; les codes de Windows figurent dans les messages d'échec.

### Installation

Téléchargez `CyberArkTerm-0.4.2-win-x64.zip`, décompressez-le et lancez `CyberArkTerm.exe` (Windows 10 ou 11 x64, aucun runtime ni droit administrateur requis). L'empreinte SHA256 est dans `SHA256SUMS.txt`. L'exécutable n'est pas signé : SmartScreen peut demander « Informations complémentaires » → « Exécuter quand même ». Depuis une version précédente, remplacez simplement l'exécutable : vos paramètres sont conservés, et le journal de débogage reste désactivé.
