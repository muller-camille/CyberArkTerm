Les composants PSM en application distante (RemoteApp), comme PSM-RDP sur certains PSM, s'affichent maintenant dans l'onglet au lieu de fenêtres séparées.

### Nouveauté

**Applications distantes PSM dans l'onglet**
- Le fichier RemoteApp renvoyé par le PVWA contient aussi la demande de session PSM (`alternate shell:s:PSM@…`). CyberArkTerm ouvre donc la même connexion comme un bureau, sans le mode RemoteApp, comme une connexion PSM classique : la session s'affiche dans l'onglet.
- Ce comportement est activé par défaut : Paramètres → Bureau à distance (RDP) → « Afficher les applications distantes PSM dans l'onglet, comme un bureau ».
- Le serveur PSM doit accepter les sessions en bureau. Si la session se termine dans la première minute, l'onglet indique que le PSM refuse peut-être ce mode et quelle option décocher. Une fois l'option décochée, l'application s'ouvre en fenêtres séparées, comme en 0.4.0.

### Vérifications

- Un fichier RemoteApp de PVWA (valeurs masquées) est converti comme attendu ; un fichier sans programme de démarrage ne l'est pas.
- Sur un vrai Windows de CI, la connexion convertie s'ouvre en bureau dans l'onglet et le programme de démarrage est transmis au contrôle Bureau à distance. Le poste de CI n'a pas le rôle « Hôte de session Bureau à distance » et ne lance pas ce programme ; un serveur PSM, si. C'est donc avec votre PSM que le lancement de la session se confirme.

### Installation

Téléchargez `CyberArkTerm-0.4.1-win-x64.zip`, décompressez-le et lancez `CyberArkTerm.exe` (Windows 10 ou 11 x64, aucun runtime ni droit administrateur requis). L'empreinte SHA256 est dans `SHA256SUMS.txt`. L'exécutable n'est pas signé : SmartScreen peut demander « Informations complémentaires » → « Exécuter quand même ». Depuis une version précédente, remplacez simplement l'exécutable : vos paramètres sont conservés, et la nouvelle option est activée.
