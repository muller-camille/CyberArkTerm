Les composants PSM en application distante (RemoteApp) s'ouvrent maintenant dans CyberArkTerm, sans passer par la Connexion Bureau à distance (mstsc).

### Nouveautés

**Applications distantes (RemoteApp) avec le contrôle intégré**
- Quand le PVWA renvoie une connexion en application distante, CyberArkTerm la lance avec le contrôle Bureau à distance de Windows, comme les sessions de bureau.
- Les fenêtres de l'application s'ouvrent à part, sur votre bureau, comme avec mstsc. L'onglet indique « Application distante « … » ouverte » : **Déconnecter** la ferme, **Reconnecter** la relance.
- L'application est lancée une seule fois par connexion, ce qui évite de réutiliser la demande de session PSM, valable une seule fois.
- Si le serveur refuse l'application, la session se termine avec la raison : non autorisée sur le serveur, introuvable, ou code d'erreur.
- mstsc reste utilisé si le contrôle Bureau à distance est absent ou échoue, ou si l'option est décochée dans Paramètres → Bureau à distance (RDP).

**Vérifié sur un vrai serveur Windows**
- Un nouveau test d'intégration ouvre de vraies sessions sur le poste Windows de la CI : un bureau dans un onglet, le Bloc-notes en application distante, et une application inconnue qui doit donner un message clair.

### À vérifier avec votre PSM

Le contenu exact des fichiers .rdp RemoteApp dépend de la configuration du PSM. Si une application distante ne s'ouvre pas, la barre d'état et l'onglet indiquent la raison. Décocher l'option dans les Paramètres repasse par mstsc.

### Installation

Téléchargez `CyberArkTerm-0.4.0-win-x64.zip`, décompressez-le et lancez `CyberArkTerm.exe` (Windows 10 ou 11 x64, aucun runtime ni droit administrateur requis). L'empreinte SHA256 est dans `SHA256SUMS.txt`. L'exécutable n'est pas signé : SmartScreen peut demander « Informations complémentaires » → « Exécuter quand même ». Depuis une version précédente, remplacez simplement l'exécutable : vos paramètres sont conservés.
